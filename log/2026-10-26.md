## Deployment guide pass
- Rewrote `deploy/README.md` as a step-by-step guide for a new user:
  - Docker and Tailscale;
  - an HTTPS tailnet address;
  - `.env` with three required values;
  - the master key;
  - `docker compose up -d --build`;
  - the household file and logins;
  - for each provider, where to get what the app asks for (ICS/CalDAV/Google calendars, IMAP app passwords, the Google OAuth client with the current console names), phones/ntfy and the wall screen;
  - backups, updates, a troubleshooting table, and a reference section.
- The README's Deploying section is now a summary that links to the guide. `runbooks/install.md` is now a checklist. `restore.md` and `rotate-key.md` use the new paths.
- Bugs found in the old docs:
  - `chmod 400` on the master key made it unreadable to the container user (uid 10001). Confirmed with a test container.
  - The key was created in the repo root while `./fa_master_key` resolves next to the compose file.
  - `FA_TRUSTED_PROXIES` was documented but not passed through by compose.
  - `.gitignore` did not cover a deployment's key.
- The fix:
  - The key now lives in `deploy/secrets/` (folder 700, file 444).
  - `deploy/.env` sets `COMPOSE_FILE` and `COMPOSE_PROJECT_NAME`, so plain `docker compose` works from `deploy/`.
  - `NTFY_UPSTREAM_BASE_URL` (iPhones) is passed through.
  - `.gitignore` covers `deploy/secrets/`, `deploy/household.toml` and `deploy/backups/`.
- Ran guide steps 4–6 and the backup on a throwaway stack (project `fa-guide-test`): build, healthy, `readyz: ready`, import (re-run is idempotent), two `user add`, and a dump written. Torn down, with 0 dangling volumes. Not verified: the Tailscale steps and the provider-side screens (no accounts used).
