# 2026-10-30

## Remove the household TOML (D-089)
- Instruction (not a question): the household TOML is legacy since the wizard (D-065) and the UI-owned settings (D-075); remove it from the backend and update the README. Recorded as D-089 (`source_questions: []`); D-018 is superseded.
- Backend: `fa-config` now holds only process and runtime settings plus `create_household` (the wizard's first step, error type `HouseholdError`). Deleted the TOML schema, `import`, `export`, the `mail`, `tasks` and `feeds` config modules and their tests, the `toml` and `insta` workspace dependencies, `fa-store`'s `ConfigExtRepo`, `POST /api/v1/config/import`, `GET /api/v1/config/export`, `fa-server config import|export` and their tests. `fa.toml` (process config through figment) is not household data and stays.
- `fa-server user add`, `pin set` and `notify test` take `--member <display name>` (case-insensitive) instead of the TOML member key. The `member.config_key` column stays (deployed migration) but nothing writes it.
- Web: removed the Settings, System "Household file" card, the wizard's import option, `api.exportConfig`/`importConfig`, the `text`/`asText` request options and the two Playwright checks for it; regenerated `openapi.json` and `api.d.ts`.
- Seeding: `config/examples/household.example.toml` is gone. New `e2e/seed-household.mjs` creates the same fictional family through the setup API; `scripts/e2e.sh` and `scripts/demo-reset.sh` use it (both now start the app before seeding). The old example's disabled "School calendar" source and the org calendar links are not seeded (the API needs an ICS URL; no spec used them).
- Docs: README (run-locally step 3, the two "Household TOML" sections, inline TOML mentions, the CLI table), `deploy/README.md`, `arch/` Overall, Platform, Frontend, Feeds, Ingest and Tasks, and the Overall diagram (regenerated).
- Disk was full mid-build: ran `cargo clean` (deps were 29 GB, per the disk rule).
