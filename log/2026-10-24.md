## CI failure after H-01 (first push)
- The `rust` job failed at clippy (exit 101), with deny, hygiene, and web green. There were two root causes, both reproduced locally against a **fresh** `pgvector:pg16`:
  1. **`DATABASE_URL` was set for the whole job**, so the sqlx `query!` macros checked against the empty service DB (`relation "household" does not exist`). Fix: `SQLX_OFFLINE: "true"` at job level, so compile-time checks use the committed `.sqlx/`. `DATABASE_URL` stays for the runtime `#[sqlx::test]`. The separate offline-check step was removed as redundant.
  2. **A `CREATE ROLE fa_app` race in migration 0001.** `#[sqlx::test]` migrates many DBs of one cluster in parallel, and `pg_advisory_xact_lock` is per-database, so it didn't serialise a cluster-wide CREATE ROLE (duplicate key on `pg_authid`). It passed locally only because the dev cluster already had the role. Fix: CREATE ROLE and GRANT now tolerate a concurrent creator (exception handlers). The advisory lock was removed.
- **Migration 0001 was edited after being applied.** That's acceptable pre-release, since nothing has been deployed. The dev DB checksum was updated in `_sqlx_migrations`.
- Verified:
  - 3 fresh-cluster runs pass 78 of 78, under CI-like env (SQLX_OFFLINE plus the empty DB).
  - The dev DB passes 78 of 78, and `fa-server migrate` works.
  - Clippy, fmt, and actionlint are clean.
- Also noted from the run: actions/checkout v4 targets Node 20 (deprecated, forced onto 24). Dependabot's github-actions PRs should bump it.
- Self-learn: a local "green" depended on dev-DB state (an existing role, migrated tables). CI-equivalent checks must run against a **fresh** Postgres. Added to CLAUDE.md.
