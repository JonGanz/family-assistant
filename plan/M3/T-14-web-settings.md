## Work
1. **Settings → Mail** (`SettingsMailView.vue` + parts): sources (add Gmail: if the adult's Google account lacks Gmail scopes, a "Connect Gmail" button goes to `/api/v1/oauth/google/start?purpose=gmail_read|gmail_modify&return_to=/settings/mail`; add IMAP with host/port/username/app password and "Test connection" via `POST /mail-sources/imap/test`, pre-filling `imap.gmail.com:993` and `[Gmail]/All Mail` for Gmail addresses; owners, visibility, read-only, backfill, filter, folders, poll, state, Sync now, pause/resume, archive), categories (behaviour, notify, auto actions, email tasks, archive, add), rules (list + a condition builder with field/op/values rows, value input per decision point, "Test on recent mail"), built-in signals toggles, and household mail settings (auto-write switch default off with thresholds, inbox expiry, gender term lists, currency, bill lead days, retention policy) — the household ones may live in `SettingsHouseholdView.vue` instead; pick one place and link from the other.
2. **Settings → Organizations** (`SettingsOrgsView.vue`): orgs (kind, name, domains, senders, ICS feed calendar, default calendar, contact mode, bill template), contacts per org, and enrollments per child (org, grade, class, dates, contacts).
3. **Members** editor: aliases, and for children gender (optional, "not set" default) and relevance tags (chip input); visible to adults only.
4. **Notifications** settings: `approval_needed` mode (immediate / batched / digest only / off) and the `mail_time_sensitive` toggle for adults.
5. **Dashboard** `inbox` panel kind (add to the panel registry, layout editor and presets list but not to the default presets): shows `snapshot.inbox` counts; when the device is elevated (PIN step-up, existing flow), loads `GET /inbox` with the device bearer and offers approve/reject for events, bills and tasks (contacts: count only). Refetch on SSE `inbox.updated`.
7. **Settings → Calendars:** a per-source "Allow writing (approved events)" toggle (`writable`; for Google sources whose account lacks `calendar.events`, a "Connect for writing" button to `/api/v1/oauth/google/start?purpose=calendar_write&return_to=/settings/calendars`) and a per-calendar "Default target" toggle (`is_default_target`), using the fields T-12 adds to the source and calendar PATCH routes.
6. Stores and API module `api/mailSettings.ts` (don't edit `client.ts`; T-13 owns it), with vitest tests.
