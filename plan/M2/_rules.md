# Ground rules (all M2 tasks)

- **Repo:** `/home/jon/projects/family-assistant`. First read `CLAUDE.md`, `plan/M2.md` (especially *Contracts fixed up front*), and the arch sections your brief lists. The contracts in `plan/M2.md` are the source of truth. If one is wrong or missing, don't invent a new public contract: work around it minimally inside your own paths and report it.
- **Edit only the paths you own.** The root `Cargo.toml` belongs to the main session. Add dependencies to your crate only as `workspace = true` entries. If a workspace dependency is missing, report it.
- **Real data rule:** the dev DB (`postgres://fa:fa@127.0.0.1:55432/fa`) holds a real household. **Never read or print its rows.** You may run migrations against it and `cargo sqlx prepare` (schema only). Tests use `#[sqlx::test]` or a throwaway container.
- **Disk:** run `df -h /` before building. If less than 6 GB is free, stop and report. Build with `CARGO_INCREMENTAL=0`.
- **Throwaway containers** are removed with `docker rm -f -v <name>` (the `-v` avoids leaking volumes). Fresh Postgres for CI-equivalent checks: `docker run -d --name fa-<task> -e POSTGRES_PASSWORD=fa -p <port>:5432 pgvector/pgvector:pg16`, then `SQLX_OFFLINE=true DATABASE_URL=postgres://postgres:fa@127.0.0.1:<port>/postgres cargo test -p <crate>`, then `docker rm -f -v fa-<task>`. Pick a port in 55400–55499 from your task number (T-04 → 55404).
- **External names:** verify crate features with `cargo add --dry-run` before relying on them. Don't guess API paths. ntfy's API is verified in `plan/M2.md` *Notifications*.
- **Code style:** idiomatic Rust 2024, `thiserror` in libraries, `anyhow` only in bins, no `unwrap()` outside tests, `tracing` for logs (never log secrets, tokens, topics, or feed URLs). Sparse comments. Match the surrounding code (`XxxRepo` associated functions taking `&mut PgConnection` and returning `Versioned<T>`; services holding a `Store`; jobs as `JobHandler` impls with `handlers()` and `default_schedules()`).
- **Time:** all household-local date math goes through the pure helpers in `fa_domain::tasks`, `fa_domain::routines`, and `fa_domain::notify` (T-01). Use `chrono-tz` with `household.tz`.
- **Format:** always run `cargo fmt` (and `corepack pnpm@9 run format` for web) before reporting.
- **Web:** no hand-written API types. `apps/web/src/gen` is generated by the main session. pnpm is `corepack pnpm@9`.
- **Public AGPL repo (D-035):** no real personal data. Fixtures use `example.com` and fictional names.
- **Git:** don't commit, and don't run `git` commands that change state.
- **Report** (your final message), concise:
  1. what you built (files);
  2. acceptance command results (pass or fail, with output on failure; quote counts only from actual output);
  3. deviations from the arch docs or contracts, and why;
  4. follow-ups, or requests for other tasks' paths;
  5. README changes needed (if your task adds commands, env vars, or setup and you don't own the README).
