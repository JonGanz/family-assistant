# M4 UI revamp and LLM extraction slice: Implementation Plan

## Why
On 2026-11-04 the user asked for two pieces of work in parallel (D-097):
- **Track A, UI revamp** (D-095, D-096): a consistent, mobile-first design language for everything outside the kiosk dashboard. It means reusable components, a new navigation, iconography and a single way of applying changes, with Material 3 as the inspiration and the existing theme variables kept (D-079).
- **Track B, AI support** (D-093, D-094): the LLM extraction slice. The System 2 LLM is reached over a configurable OpenAI-compatible endpoint (Ollama on the GPU PC by default, no custom agent). An `llm` pipeline stage serves email, a recipe-extraction contract is ready for M5, and there is a basic eval. The AI screens come last, built on track A's components.

Checked against the code (2026-11-04):
- `StageKind::Llm` already exists in `fa-domain` and is skipped by `fa-pipeline::Pipeline::run`.
- There is no `fa-llm`, `fa-decide` or recipe code yet, and `bins/fa-gpu-agent` is a 3-line stub (left as is, M4.1).
- `reqwest 0.13.5`, `scraper 0.29` and `axum 0.8.9` are workspace dependencies; `schemars` is not.
- `fa-connectors/src/http.rs` holds the private-IP guard.
- The web app has no UI library: one `styles/base.css`, ad-hoc components in `components/`, a text-only top nav in `layouts/AppLayout.vue`, and 26 views.
- Six views have their own Save logic and the others save on change.

Research: R-004 covers the OpenAI-compatible API, Ollama `json_schema` support since v0.5.0, plain `reqwest` over `async-openai`, and `qwen3:8b` as the default model tag. R-005 covers Material Symbols through `unplugin-icons` and `@iconify-json/material-symbols`, with Vite 8 compatibility still unverified (T-02 verifies it).

## Done means
1. **Design system:** `apps/web/src/ui/` holds the token file and the component library listed under *UI library*, every colour taken from theme variables. A dev-only gallery at `/ui-gallery` shows every component in every state, and `scripts/ui-shots.sh` writes screenshots of the gallery and the app pages at 3 widths × light/dark.
2. **Navigation:** a bottom bar on compact screens, a rail on medium and a drawer on expanded, all built from one destinations list. The inbox badge is kept, and every destination has an icon.
3. **Every non-dashboard view** (the 26 in `apps/web/src/views/` other than `DashboardView`) uses the library, has no page-local colour values, and follows D-096. Switches and single choices apply instantly with an Undo snackbar; multi-field forms use the Save/Discard bar with a leave guard. The old `PageHeader`, `StateBlock`, `ErrorBanner` and `Tabs` components are removed or re-exported from `ui/`.
4. **LLM endpoint:** an adult can set the base URL, model, optional API key, timeout and enabled flag in Settings → AI, test the connection (latency and whether the model was found) and pick the model from the server's list. The key is sealed as a secret and never returned.
5. **LLM stage:** with the endpoint enabled, email decision points (`email.category`, `email.time_sensitive`, `email.member_link`, `email.is_bill`) can have an `llm` stage enabled per point in Settings → AI. Messages whose rules fell below the threshold, plus those `ai_settings.mail_extract_mode` selects for extraction, get one `mail.llm` job. Its results are recorded as `Decision`s with `stage_kind = llm`, and its extracted events, bills and tasks reach the approval inbox with `extracted_by = llm`, shown as an "AI" chip with the confidence. With the endpoint off or unreachable, behaviour equals M3 and jobs wait (`on_unavailable: queue`).
6. **Recipes:** `POST /ai/recipes/extract` with a URL or HTML returns a `RecipeDraft`, from schema.org JSON-LD when present (`origin: "jsonld"`), else from the LLM (`origin: "llm"`). Nothing is stored (M5 stores recipes).
7. **Eval:** `fa-server eval --decision-point <dp> [--with-llm] [--limit N]` replays the labelled sample (D-028) and prints accuracy, coverage and p50/p95 latency per stage. `GET /ai/stats` feeds a stats card in Settings → AI.
8. **Observability without content:** every LLM call writes an `llm_call` row (purpose, model, latency, ok or error kind, token counts) with no prompt or response text. The rows are pruned after 90 days.
9. **Review checkpoints** R1 to R4 (below) are held, and each one's feedback is closed or carried into a listed follow-up.
10. Closing checklist of CLAUDE.md workflow 8: `scripts/ci-local.sh`, `scripts/e2e.sh` and `scripts/compose-smoke.sh` are green, the README (AI setup, roadmap) is updated with its steps verified, and 0 dangling volumes.

### `fa-llm` (T-04 client; T-06 adds `provider.rs`)
```rust
pub struct EndpointConfig { pub base_url: url::Url, pub model: String, pub api_key: Option<String>,
                            pub timeout: Duration, pub dialect: Dialect }
pub enum Dialect { OpenaiChat, OllamaNative }
pub struct LlmClient;                      // cheap to clone; holds a reqwest::Client
impl LlmClient {
  pub fn new(cfg: EndpointConfig, http: reqwest::Client) -> Self;
  pub async fn extract<T: serde::de::DeserializeOwned + schemars::JsonSchema>(&self, req: &ExtractRequest) -> Result<Extracted<T>, LlmError>;
  pub async fn models(&self) -> Result<Vec<String>, LlmError>;   // GET {base}/models (OpenAI shape); Ollama native: /api/tags
  pub async fn ping(&self) -> Result<Ping, LlmError>;             // models() + model present
}
pub struct ExtractRequest { pub system: String, pub user: String, pub schema_name: &'static str, pub max_tokens: u32 }
pub struct Extracted<T> { pub value: T, pub latency: Duration, pub prompt_tokens: Option<u32>, pub completion_tokens: Option<u32> }
pub struct Ping { pub latency: Duration, pub model_found: bool }
pub enum LlmError { Unavailable(String), Timeout, Http(u16), BadJson(String), Schema(String), Config(String) }  // thiserror
impl LlmError { pub fn kind(&self) -> &'static str }  // the llm_call.error_kind values
```
- `openai_chat`: `POST {base_url}/chat/completions` with `{"model", "messages":[system,user], "response_format":{"type":"json_schema","json_schema":{"name":schema_name,"schema":<schemars>,"strict":true}}, "max_tokens", "temperature":0}`, an `Authorization: Bearer <key>` header when a key is set, and the content of `choices[0].message.content` parsed into `T`.
- `ollama_native`: `POST {base_url}/api/chat` with `"format": <schema>`, `"stream": false`, `"options":{"temperature":0}`. Here `base_url` has no `/v1`.
- Connection refused or a DNS failure is `Unavailable`. The timeout comes from `cfg.timeout`.
- Private and LAN hosts are allowed: the endpoint is set by an adult (no `is_private_ip` guard), but redirects are disabled.
- Tests run against an in-process `axum` stub server; no new test dependency.

  pub async fn call<T: DeserializeOwned + JsonSchema>(&self, household: HouseholdId, purpose: &'static str, req: &ExtractRequest) -> Result<Extracted<T>, LlmError>; // permit, call, write llm_call

### `llm` stage and the `mail.llm` job (T-06; `fa-pipeline`, `fa-mail`)
- `fa_pipeline::Pipeline::run` still stops at the first stage it cannot run inline. When the next enabled stage after a below-threshold `rules` result is `llm`, the `Outcome` has the new field `pending_llm: bool = true`, and the default value applies meanwhile (as for `human`).
- New: `Pipeline::record_stage(conn, subject, dp, StageKind::Llm, candidates, version) -> Outcome`. It accepts a candidate at or above the `llm` stage's threshold; otherwise the decision falls through to `human`.
- `mail.process` enqueues one job `mail.llm` `{ "message_id": uuid }` per message when the endpoint is enabled and either of these holds:
  - some decision point has `pending_llm`;
  - the category's behaviour is `extract` and either `mail_extract_mode = always`, or `fallback` and no rule extractor produced an item at ≥ 0.8.
  It enqueues no duplicate per message.
- The `mail.llm` job makes **one** call per message (`purpose = "mail.llm"`) with schema `MailLlmResult` (in `fa-mail`, derives `JsonSchema`). Only the parts asked for are requested:
  ```
  { category?: {value: <category key>, confidence: 0..1},
    time_sensitive?: {value: bool, confidence}, is_bill?: {value: bool, confidence},
    member_link?: [{member: <member key>, confidence}],
    events?: [{title, start: RFC 3339 or "YYYY-MM-DD" (all-day), end?: same, location?: string, confidence}],
    bills?: [{payee, amount_cents: int, currency: "ISO 4217", due: "YYYY-MM-DD", confidence}],
    tasks?: [{title, due?: "YYYY-MM-DD", kind: "reply"|"sign"|"rsvp"|"pay"|"other", confidence}] }
  ```
  - Options in the prompt are listed in a fixed, stable order (category keys sorted, members by id).
  - Input is the subject, sender and plain-text body truncated to `ai_settings.max_input_chars`. Content is never logged.
  - Decisions are recorded with `record_stage`. If `email.category` changes, the job re-runs that message's category behaviour step (idempotent).
  - Extracted items go through the existing dedupe and inbox paths, then marked `extracted_by = llm`. Nothing is applied without approval (D-057, D-060).
- `on_unavailable = queue` means that `LlmError::Unavailable` or `Timeout` makes the job fail with the job runner's retry and backoff (`JobRepo::fail`: 30 s × 2^attempts). `mail.llm` is enqueued with `max_attempts: 12` (about a day) and idempotency key `mail.llm:<message_id>`. After the job's max attempts the message keeps its default values (the human stage).
- A job `llm.prune` runs daily (`0 4 * * *`) and deletes `llm_call` rows older than 90 days.
- `Pipeline::set_llm_stage(conn, household, dp, enabled, threshold) -> PipelineVersionId` saves a new version with an `llm` stage inserted before `human` (or updates it) and activates it. Validation is unchanged.

### `fa-recipe` (T-07)
- `pub fn from_html(html: &str, source_url: Option<&Url>) -> Option<RecipeDraft>` parses schema.org `Recipe` JSON-LD, including `@graph` and arrays, with no I/O. `pub async fn from_llm(client: &LlmClient, text: &str, source_url: Option<&Url>) -> Result<RecipeDraft, LlmError>` is the fallback.
- `pub async fn fetch_page(http: &fa_connectors::http::Http, url: &Url) -> Result<String, RecipeError>` uses the existing guarded client `Http::with_policy(true, false)`, which blocks private hosts (redirects included) and caps the body at 10 MB, with a 20 s timeout and at most 5 redirects (as built by T-07).
- `RecipeDraft` (ts-rs + `ToSchema`; lives in `fa-recipe`, which M5 will move to `fa-domain`):
  `{ name: string, source_url: string|null, origin: "jsonld"|"llm", yield_text: string|null, servings: number|null, prep_minutes: number|null, cook_minutes: number|null, total_minutes: number|null, ingredients: [{text: string, quantity: number|null, unit: string|null, item: string|null}], steps: string[], tags: string[], image_url: string|null }`.
  Minutes are integers converted from ISO 8601 durations (`PT1H30M` → 90). An unparseable duration gives `null`.
- Deterministic first: ingredient `text` is always the source line. `quantity`, `unit` and `item` come from a small rule parser (fractions and unicode fractions such as `1 ½`, ranges taking the low end, and a fixed unit list), and are left `null` when unsure.
- Test fixtures are fictional HTML pages under `crates/fa-recipe/tests/fixtures/`.
