# M5.1 Recipe sections and live scaling: Implementation Plan

## Why
User instruction of 2026-11-17 (D-124, D-125, both from instructions with the proposed defaults accepted): recipes get named sections (a chicken and its own sauce), laid out as columns of ingredient and step cards with shared ingredients above and finish steps below; the kiosk recipe view scales a recipe live (½× to 3×). Checked against the code: `recipe_ingredient` and `recipe_step` have no grouping; `fa-recipe/src/jsonld.rs` `steps()` walks `HowToSection.itemListElement` but drops the section name; ingredient heading lines ("For the sauce:") are stored as ingredients; the LLM schema is flat; `RecipeView.steps` is `Vec<String>`; the kiosk ticks (`dashboard/details/recipeChecks.ts`) are keyed by index; `RecipeLineView` already carries `qty`, `unit`, `item`; the kiosk reads `GET /recipes/{id}` (allowed on the LAN listener), not the adult-only `/meals/settings`.

## Done means
1. A recipe can have ordered, named sections; each ingredient line and step belongs to one or none. Saving, reading, updating and deleting keep them; line matches are kept across saves as before.
2. Importing a JSON-LD page with `HowToSection`s keeps the section names; heading-like ingredient lines become sections, not ingredients; ingredient groups and step sections pair by name; plugin ingredient groups are read when JSON-LD has none (if their markup could be verified); the LLM fallback may return sections.
3. The recipe editor adds, renames, reorders, merges and deletes sections and moves any line or step between sections.
4. The app recipe page and the kiosk recipe window show shared ingredients full width, one column per section (ingredients above steps, `recipe_section_columns` before wrapping, one column on phones) and finish steps full width below. A recipe without sections looks as before.
5. The kiosk recipe window has a row of scale factors (default ½ 1 1.5 2 3, 1 always offered) that scales parsed amounts and servings live and resets to 1× on open. Kiosk ticks are keyed by line and step id.
6. Settings → Meals edits `recipe_scale_factors` and `recipe_section_columns`.
7. CLAUDE.md workflow 8: `scripts/ci-local.sh`, `scripts/e2e.sh`, `scripts/compose-smoke.sh` green; README checked (no new commands expected); CHANGELOG entry; tag.

### Migration (T-02)
`crates/fa-store/migrations/20261117000001_recipe_sections.{up,down}.sql`:
- `recipe_section (id uuid PK, household_id uuid NOT NULL REFERENCES household(id), recipe_id uuid NOT NULL REFERENCES recipe(id) ON DELETE CASCADE, ord int NOT NULL, name text NOT NULL CHECK (char_length(name) BETWEEN 1 AND 100), created_at, updated_at, UNIQUE (recipe_id, ord))`, with RLS exactly like the M5 meals tables (copy the policy pattern of `20261108000001_m5_meals.up.sql`).
- `recipe_ingredient.section_id uuid NULL REFERENCES recipe_section(id) ON DELETE SET NULL`; `recipe_step.section_id` the same. (Grepped: neither table has a `section` column; `grocery_item.section` is unrelated.)
- `meals_settings.recipe_scale_factors real[] NOT NULL DEFAULT '{0.5,1,1.5,2,3}'`; `meals_settings.recipe_section_columns int NOT NULL DEFAULT 2 CHECK (recipe_section_columns BETWEEN 1 AND 4)`. Writer: `PUT /meals/settings` (Settings → Meals).
- Down drops the columns and the table.

### Types (fa-domain, T-02)
- `id_type!(RecipeSectionId)`, `id_type!(RecipeStepId)` in `ids.rs`.
- `recipe.rs`: `DraftSection { name: String, ingredients: Vec<RecipeIngredient>, steps: Vec<String> }`; `RecipeDraft.sections: Vec<DraftSection>` with `#[serde(default)]`. Top-level `ingredients`/`steps` are the shared lines and finish steps.
- `meals_api.rs`:
  - `RecipeSectionInput { name: String, lines: Vec<String>, steps: Vec<String> }`; `RecipeInput.sections: Vec<RecipeSectionInput>` `#[serde(default)]`. Top-level `lines`/`steps` = shared / finish. Validation (422): names trimmed 1..100 chars; at most 20 sections.
  - `RecipeSectionView { id: RecipeSectionId, ord: u32, name: String }`; `RecipeView.sections: Vec<RecipeSectionView>` (ordered).
  - `RecipeLineView.section_id: Option<RecipeSectionId>` (`#[ts(as = "Option<RecipeSectionId>", optional = nullable)]`).
  - `RecipeStepView { id: RecipeStepId, ord: u32, text: String, section_id: Option<RecipeSectionId> }`; **`RecipeView.steps: Vec<RecipeStepView>`** (was `Vec<String>`; ordered by `ord`).
  - `RecipeView.scale_factors: Vec<f32>` and `RecipeView.section_columns: u32`, filled from the household's `meals_settings` on every read.
  - `MealsSettingsView` gains `recipe_scale_factors: Vec<f32>`, `recipe_section_columns: u32`; `MealsSettingsPatch` gains both as `Option`. Validation (422): 1..8 factors, each 0.1..=10; columns 1..=4. Stored sorted ascending, deduplicated; 1 is added if missing.
- Ordering rule: ingredient `ord` and step `ord` stay global per recipe: shared lines first, then each section's lines in section order (steps: each section's steps in section order, then the finish steps). Readers group by `section_id`, never by `ord` ranges.

### Store and service (T-02)
- `RecipeSectionRepo::replace_for_recipe(conn, recipe, names: &[String]) -> Result<Vec<RecipeSectionId>>` (delete all, insert in order) and `for_recipe`. Save order inside the existing transaction: sections, then lines (`NewLine` gains `section_id`), then steps (`RecipeStepRepo::replace_for_recipe` takes `(text, section_id)` pairs and `for_recipe` returns rows with id, ord, text, section_id). The line-reuse rule by `raw_text` is unchanged; a reused line's `section_id` is updated.
- `fa-meals` `get_recipe`/`create_recipe`/`update_recipe` read and write sections and fill `scale_factors`/`section_columns`.

### Wire formats
No new date or time fields. Factors are JSON numbers; ids are UUID strings.

### Web scaffold (main session, after regeneration)
`apps/web/src/lib/recipeSections.ts`: `groupRecipe(r: RecipeView): { shared: RecipeLineView[]; sections: { section: RecipeSectionView; lines: RecipeLineView[]; steps: RecipeStepView[] }[]; finish: RecipeStepView[] }` (sections in `ord`, lines and steps in `ord`; a line or step whose `section_id` names no section is treated as shared/finish). T-04 and T-05 import it; neither edits it (report changes).

### Scaling (T-05)
`apps/web/src/lib/recipeScale.ts`: `formatQty(n: number): string` (¼ ⅓ ½ ⅔ ¾ glyphs within 0.02, with a whole part "1½"; else up to two decimals, trailing zeros trimmed) and `scaleLine(line: RecipeLineView, factor: number): string` (factor 1 or no `qty` → `raw_text`; else replace the leading amount in `raw_text` — integers, decimals, `1 1/2`, `1/2`, unicode fractions, ranges `1-2` / `1 to 2` scaling both ends — with the scaled amount; if no leading amount is found, `formatQty(qty*f) + (unit ? ' ' + unit : '') + ' ' + (item ?? raw_text)`).

## Out of scope
Scaling on the app recipe page; re-import of existing recipes; sub-recipes (a section that points at another recipe); scaling step text; saving the factor.
