# M3.5 Onboarding and shakedown: Implementation Plan

## Why
D-065 (user instruction, 2026-10-26): installing takes Tailscale on the host, `tailscale serve`, a required HTTPS address, a hand-made master key and `.env`, a household TOML file, and `docker compose exec api fa-server ...` to import it and create logins. That is too much. M3.5 pauses feature work to fix it, before M4. D-066 adds the real-hardware shakedown, and batch 17 plus the open review findings ([IMPROVEMENTS.md](../IMPROVEMENTS.md)) are folded in so the first real install runs the code we intend to keep. Workstreams:

| | Workstream | In one line |
|---|---|---|
| **A** | Compose deployment, optional Tailscale sidecar | `docker compose up -d` with no required settings; `--profile tailscale` adds remote access |
| **B** | HTTPS optional | Plain HTTP on the home network works; HTTPS when Tailscale or a proxy provides it |
| **C** | First-run wizard | The first browser visit sets up the household, logins and access; no TOML, no CLI |
| **D** | Batch 17 decisions | At-a-glance dashboard and self-clearing advisories (D-068), explicit trusted proxies (D-069), Members under adult Settings (D-070) |
| **E** | Review fixes | The IMPROVEMENTS.md items that touch the same code or matter on a real install (table below) |
| **F** | Shakedown | Install on the real server with the new flow, do H-02 to H-11 there, measure the inbox for a week (D-066) |

Batches 17 and 18 are answered (D-066 to D-077, 2026-10-26) and the arch docs re-derived (T-01). Where an answer differed from the first draft of this plan, the contract below was changed: no setup guard or code (D-073), no `lan_mode` and no not-encrypted banners (D-072), one container and no split override (D-076), amd64 only (D-077), interests unused until M4 (D-071).

## Done means
1. **Install in two commands.** On a machine with Docker: download `compose.yaml` (or clone), `docker compose up -d`. No `.env` edits, no key files, no build. Opening `http://<server>:8080` shows the wizard. Measured on the real server (H-13): under 15 minutes to a logged-in adult, excluding the image download.
2. **Tailscale is one profile.** `TS_AUTHKEY=... docker compose --profile tailscale up -d` puts the app on `https://<name>.<tailnet>.ts.net` with a real certificate, and ntfy on `:8443`. Without the profile, nothing Tailscale-related runs.
3. **HTTP and HTTPS both work.** Login, the dashboard, pairing, notifications and every e2e spec pass over plain HTTP from a LAN address, and over HTTPS behind a proxy. The session cookie is `Secure` exactly when the request arrived over HTTPS. Nothing refuses to start because of the scheme.
4. **The wizard replaces setup commands.** A fresh database shows `/setup`; finishing it leaves a household, its members, one adult login (plus optional others), PINs, the public address, notification settings and a confirmed master-key backup. `config import`, `user add` and `pin set` are no longer in the install guide (they remain for recovery and scripting).
5. **TOML stays optional.** Settings, System offers export (download) and import (upload with a dry-run preview), the same code paths as the CLI (D-018).
6. **Existing installs keep working.** Every current `FA_*` variable is still honoured and overrides the UI.
7. **Batch 17 is in:** the dashboard shows no inbox and no mail-derived content beyond a per-adult pending count (D-078), each adult's inbox holds only items from sources they may see, advisories have no dismiss and disappear when their rule stops matching or `valid_until` passes, `/members` is gone and `/settings/members` is adult-only, devices are refused `ReadInbox`, the default trusted proxies are loopback only.
8. **The review items in workstream E are closed** in `plan/reviews/2026-10-26-repo-review.md` and IMPROVEMENTS.md.
9. **Shakedown (after the code closes):** H-02 to H-14 done on the real server; a week of inbox numbers (proposals per day by kind, approve/reject ratio) recorded in `## Outcome`; they pick M4's first decision points (D-067).
10. Checklist of CLAUDE.md workflow 8: `scripts/ci-local.sh`, `scripts/e2e.sh` (run by the main session) and `scripts/compose-smoke.sh` green; 0 dangling volumes; README and `deploy/README.md` verified by running them from an empty Docker host.

## Workstream A: compose deployment, optional Tailscale sidecar
**Target layout** (`deploy/compose.yaml`, replacing `compose.example.yaml`; `.env` becomes optional overrides only):

| Service | Profile | Image | Notes |
|---|---|---|---|

| `postgres` | default | `pgvector/pgvector:pg16` | `POSTGRES_PASSWORD_FILE=/run/fa-secrets/db_password`. Not published |
| `app` | default | `ghcr.io/jonganz/fa-server:<tag>` | `serve all`, the only app container (D-076). Publishes `${FA_HTTP_PORT:-8080}` on `${FA_HTTP_HOST_IP:-0.0.0.0}`: the whole app over HTTP (D-072). Reads the DB password from the secrets volume |
| `ntfy` | default | `binwiederhier/ntfy:v2.17.0` | Published on `${FA_NTFY_PORT:-8090}`; `NTFY_BASE_URL` set by the app's public address where possible, else the LAN address |
| `backup` | default | `prodrigestivill/postgres-backup-local:16` | Defaults to the named volume `fa-backups`; `BACKUP_DIR` overrides with a NAS path |
| `tailscale` | `tailscale` | `tailscale/tailscale:<pinned>` (name verified with `docker manifest inspect tailscale/tailscale:stable` on 2026-10-26; pin a version in T-04) | `TS_AUTHKEY`, `TS_HOSTNAME` (default `family`), `TS_STATE_DIR=/var/lib/tailscale` on volume `ts-state`, `TS_SERVE_CONFIG=/config/serve.json` (`deploy/tailscale/serve.json`: 443 → `http://app:8080`, 8443 → `http://ntfy:80`). | `ollama` etc. | `gpu`, `ai-cpu` | as today | unchanged |

- **Trusted proxy (D-069):** the built-in default is loopback only. The compose network gets a fixed subnet and the sidecar a fixed IP, and the compose file sets `FA_TRUSTED_PROXIES` to loopback plus that IP. Closes C-04.
- **`X-Forwarded-Proto`:** `tailscale serve` sets it; T-05 uses it (from trusted proxies only) for the cookie and for detecting the public address.
- **Image (D-077):** `.github/workflows/release-image.yml` builds `linux/amd64` on `v*` tags and pushes `ghcr.io/jonganz/fa-server`. `build:` stays in a `compose.build.yaml` override for developers and other architectures.
- **Host Tailscale** (today's way) stays in `deploy/README.md` as "Advanced: Tailscale on the host".
- **Override files:** `compose.build.yaml` only (build locally). No split layout (D-076).

## Workstream B: HTTPS optional
- **`fa-config`:** drop the "https required unless localhost" startup error. `FA_COOKIE_SECURE` becomes `auto | true | false`, default `auto`. `FA_PUBLIC_BASE_URL` becomes optional (it overrides the stored setting).
- **Per-request scheme:** `auto` sets `Secure` when the request came over TLS, or from a trusted proxy with `X-Forwarded-Proto: https`. Never send HSTS.
- **Public address without config:** links that a request produces (pairing links, OAuth redirect) use the stored `public_base_url` setting, which the wizard fills from the browser's `location.origin` and Settings, System can change. Links produced without a request (notification click URLs in the worker) use the stored setting only. With the sidecar, both the LAN and tailnet addresses are stored, and pairing offers both (as D-064 does today).
- **LAN exposure (D-072):** the entire app over HTTP, PIN elevation included. No banners: Settings, System states the connection type as a fact. No `lan_mode`. The D-064 listener stays an opt-in restricted port with its own `FA_LAN_ALLOW_PIN`.
- **Insecure-context audit of the web app (T-07):** no service worker registration when `!isSecureContext` (the app must load without it); replace `crypto.randomUUID`, `crypto.subtle` and `navigator.clipboard` uses with fallbacks; the PWA install hint hidden on HTTP.
- **Google sign-in** needs HTTPS (Google rejects `http://` redirect URIs except localhost). On HTTP, Settings shows Google as "needs HTTPS (turn on Tailscale)" instead of hiding it.
- **Child passwords (D-031):** the 4-character minimum stays.

## Workstream C: first-run wizard
**State:** setup is needed while no household exists. While needed, every `/api/v1/*` call except `/setup*`, `/healthz`, `/readyz` returns `409 {"error":"setup_required"}`, and the web router sends every route to `/setup`.

**Protection (D-073):** none beyond one-shot: the first visitor runs it. Once the first adult account exists, the setup writes return 409 for good. The guide says to finish setup right after starting.

**Steps** (each step saves; the wizard can be resumed, and back/next keeps values):
1. **Welcome.** Detected address, HTTP or HTTPS, whether the Tailscale sidecar is up.
2. **Household.** Name, time zone (browser default), location (city search through the Open-Meteo geocoding API, `geocoding-api.open-meteo.com/v1/search`, checked 2026-10-26; or lat/lon by hand), units, currency.
3. **You.** The first adult: display name, colour, username, password (12+), optional PIN. Creates the session; the rest of the wizard runs as that adult.
4. **Family.** Add adults and children (role, display name, colour, optional grade and aliases), each with an optional login and PIN. Reuses the `/settings/members` components (D-070).
5. **Access and notifications.** The public address(es), ntfy on or off with a "send a test" button (`notify test` today).
6. **Master key backup (D-074).** Show the key as base64 with Copy and Download buttons; continuing requires ticking "I stored it somewhere safe". Settings, System warns until confirmed.
7. **Start.** Optional starter chores and routines (D-047), or "Import a household file" (TOML upload, dry-run preview first). Then links to Calendars, Mail, Devices (pair the wall screen).

Steps 4 to 7 use existing API routes (`/api/v1/members`, `/members/{id}/account`, `/members/{id}/pin`, `/household`, task templates) plus the system and config routes. The exact routes, DTOs and runtime-settings keys are in *Contracts fixed up front*.

## Workstream D: batch 17 decisions
- **Dashboard at a glance (D-068):** the `inbox` panel, its DTO fields and its D-064 allowlist entries go. `Policy` refuses `ReadInbox` for every device actor, elevated or not. Approvals stay in `/inbox` in the app.
- **Advisories (D-068):** no dismiss: `DismissAdvisory`, `POST /api/v1/advisories/{id}/dismiss`, the panel's button and the `advisory.dismissed_at/_by` columns are removed (new migration). `weather.evaluate` deletes (or ends) an active advisory whose rule no longer matches the latest forecast; expiry at `valid_until` as today.
- **Private approvals (D-078):** the inbox query, counts, approve/reject and `approval_needed` recipients are scoped to the adults who may see the item's source message (owners, or all adults for `household` sources; orphaned items fall back to all adults). The dashboard data carries a count per adult, shown as a badge on the `members` strip unless the household turns `dashboard_pending_approvals` off (Settings, Household).
- **Trusted proxies (D-069):** default loopback only (workstream A sets the sidecar address).
- **Members (D-070):** `/members` removed with no redirect; `/settings/members` adult-only inside the U-08 settings layout; member writes adult-only in `Policy`; the dashboard gets a `members` strip (names, avatars, colours) for everyone.
- **Interests (D-071):** no code change; they stay stored for M4.

- **Setup-required layer:** while `needed` or `owner_needed`, every `/api/v1/*` call except `/setup*`, `/healthz` and `/readyz` returns 409 with problem code `setup_required`.
- **`ApiConfig` gains:**
  - `cookie_secure: fa_config::CookieSecure`, which replaces the bool;
  - `runtime: Arc<fa_config::RuntimeSnapshot>`;
  - `master_key_path: PathBuf`;

- **Pairing links:** they use `tailnet_base_url` when the request is secure and it is set, else `effective_base_url()`. With the D-064 listener on, the LAN link is added as today.

### Server (T-07)
- `serve` resolves settings in a loop. Each pass:
  1. reads `InstanceSettingRepo::all` and decrypts the secrets;
  2. calls `load_layered`;
  3. builds the services and runs;
  4. on a `fa_settings` notification, cancels and starts the next pass; on SIGTERM, exits.
- An applied setting change is an in-process restart of about a second. SSE clients reconnect with `Last-Event-ID`. The feature crates need no reload code.
- `init` (T-04) runs before any config is loaded.

  - `FA_LOG_FORMAT=json`
  - `FA_BACKUP_DIR=/backups`
  - `FA_DEFAULT_NTFY_URL=http://ntfy:80`
  - `FA_DEFAULT_TRUSTED_PROXIES=127.0.0.0/8,::1/128,172.30.89.10`
- The `FA_DEFAULT_*` values are defaults, not locks, so the UI can change them.
- `init` runs as root and writes into the `fa-secrets` volume:
  - `master_key`: 32 random bytes, mode 0400, owned by uid 10001;
  - `db_password`: 48 hex characters, mode 0444, which the postgres entrypoint reads after dropping to uid 999.
- Existing files are never overwritten.

## Risks and open points
- **Plain HTTP** sends passwords and PINs unencrypted on the LAN; accepted as the hoster's choice (D-072).
- **Wizard hijack** between `docker compose up` and finishing setup: accepted (D-073); the guide says to finish setup at once.
- **Losing the secrets volume** loses the master key. The wizard step and the System warning (D-074) exist for this; `restore.md` must cover it.
- **Removing advisory dismiss** needs a migration dropping columns; the dev DB has data, so the down migration restores the columns empty.
- **Settings reload:** consumers that cache config at start (`AppState`, the worker's notify client) must read through the settings handle; T-01 lists each one.
