# M5.3 Dashboard and food polish, tailnet path to Ollama: Implementation Plan

## Why
User instruction of 2026-11-20 (small UI changes, no decision records) plus a bug report: with the Tailscale sidecar, an Ollama host on the tailnet only works when entered by its LAN IP. Checked against the code: the kiosk Add task form (`dashboard/TaskFlow.vue`) hand-rolls `.modal` while the other popups use the shared `dashboard/Modal.vue`; `RecipeDetail.vue` is another hand-rolled `role="dialog"`; `WeatherPanel.vue` opens the weather detail only from its inner section (the card's padding does not); the dashboard week bar (`DashboardCanvas.vue`, `weekOffset`) has previous/next only; the Food > Meal Plan agenda (`views/food/MealPlanView.vue`) has an add button per slot below each slot's list; `RecipeView.vue` back is `router.push('/food/recipes')`. The compose `tailscale` service runs `TS_USERSPACE=true` and only serves inbound HTTPS to `app`; the `app` container is not on the tailnet and `fa_llm::default_http()` has no proxy, so tailnet addresses cannot be reached from it.

## Done means
1. Every dashboard popup that is a modal uses `dashboard/Modal.vue` (Add task form, the "who did it" picker, the recipe window); the elevation popover is a popover and stays.
2. Clicking anywhere on the Home weather card (padding included) opens the weather detail.
3. The dashboard week bar has a Today button, enabled only away from the current week; the Meal Plan page has a Today control that brings today's date into view.
4. On Food > Meal Plan each date heading carries one right-aligned always-present `[+]` (writable days), replacing the add button row per slot.
5. The recipe page back button goes to the previous page, falling back to the recipe list when there is no history.
6. An Ollama endpoint on the tailnet works from the app container (T-05, after research R-009).
7. CLAUDE.md workflow 8: `scripts/ci-local.sh`, `scripts/e2e.sh`, `scripts/compose-smoke.sh` green; screenshots of the changed kiosk UI viewed; CHANGELOG entry; tag.
