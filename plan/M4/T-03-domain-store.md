# T-03: Domain + store: AI tables, types, repos, `extracted_by`

You are a sub-agent implementing one task of milestone M4 of the Family Assistant project, a self-hosted family organiser with a Rust backend and a Vue frontend. M4 runs a UI revamp (track A) and an LLM extraction slice (track B) in parallel. This task is track B's foundation. Every other Rust task depends on these `fa-domain` types and `fa-store` repos, so it is a single task in wave 1.

## Work
1. **Migration** `crates/fa-store/migrations/20261104000001_m4_llm.up.sql` and `.down.sql`, exactly as *Database (T-03)* in the plan, with these points:
   - `llm_endpoint` with `UNIQUE (household_id)`, the CHECKs on `dialect` and `timeout_ms`, and the defaults.
   - `ai_settings` (PK `household_id`, CHECKs, defaults).
   - `llm_call` with the index `(household_id, started_at DESC)`.
   - `extracted_by text NOT NULL DEFAULT 'rules' CHECK (extracted_by IN ('rules','llm'))` on `event`, `bill` and `task`.
   - RLS on all three new tables, like the other household tables: enable it, add the `household_id = current_setting('app.household_id')` policy and grant to `fa_app`. Copy the existing pattern exactly.
   - The down migration drops everything it added.
2. **`fa-domain`** types, with ts-rs export to `apps/web/src/gen/types/` and `ToSchema`, following the existing derive sets:
   - `LlmDialect { OpenaiChat => "openai_chat", OllamaNative => "ollama_native" }`, `MailExtractMode { Off, Fallback, Always }` and `ExtractOrigin { Rules => "rules", Llm => "llm" }`, all via `db_enum!`.
   - `LlmEndpointId`, using the id macro.
   - `LlmEndpoint` (the row).
   - `LlmEndpointView { base_url: String, model: String, dialect: LlmDialect, has_api_key: bool, timeout_ms: u32, enabled: bool, updated_at: DateTime<Utc> }`, where `updated_at` is RFC 3339.
   - `AiSettings { mail_extract_mode: MailExtractMode, max_input_chars: u32, updated_at: DateTime<Utc> }`, with the defaults as a `Default`-like constructor.
   - `LlmCallStat { purpose: String, total: i64, ok: i64, p50_ms: Option<i64>, p95_ms: Option<i64> }` and `StageCount { decision_point: String, rules: i64, llm: i64, human: i64 }`, which T-08 uses for `/ai/stats`.
   - Add `extracted_by: ExtractOrigin` to `BillView`, `EventProposalView` and `TaskView` (so `GET /inbox` carries it), and update the struct literals listed under *You own*.
3. **`fa-store`** repos, all with runtime queries and the `XxxRepo` associated-function style taking `&mut PgConnection`, exported from the crate root like the others:
   - `LlmEndpointRepo::get(conn, household) -> Result<Option<LlmEndpoint>>` and `upsert(conn, household, &LlmEndpointInput) -> Result<LlmEndpoint>` (the input has no key; the key goes through the existing secret repo with `owner_type = "llm_endpoint"`, `owner_id = endpoint id`, `kind = "api_key"`). Check that the secret owner-type enum or check constraint accepts `llm_endpoint`, and extend it in the migration if it doesn't.
   - `AiSettingsRepo::get_or_default(conn, household) -> Result<AiSettings>` (no row means the defaults) and `update(conn, household, mode, max_input_chars) -> Result<AiSettings>` (an upsert).
   - `LlmCallRepo::insert(conn, &NewLlmCall)`, `prune_before(conn, cutoff: DateTime<Utc>) -> Result<u64>` (household-scoped through RLS; T-06 calls it per household), and `stats_since(conn, household, since) -> Result<Vec<LlmCallStat>>` (`percentile_cont` for p50 and p95).
   - `DecisionRepo::stage_counts_since(conn, household, since) -> Result<Vec<StageCount>>`: counts `decision` rows per decision point and stage kind.
   - `ExtractedByRepo::set(conn, target: ExtractTarget, id: Uuid, by: ExtractOrigin) -> Result<()>` with `ExtractTarget { Event, Bill, Task }`. Existing insert functions stay unchanged (the default `rules` applies); T-06 calls `set` after it inserts an LLM item.
   - Every read of `event`, `bill` and `task` that builds the three views selects `extracted_by`.
4. **Tests** (`crates/fa-store/tests/`, `#[sqlx::test]` or a fresh container):
   - endpoint upsert, then get (a second upsert updates the same row);
   - `ai_settings` defaults when there is no row, then the update;
   - `llm_call` insert, stats and prune;
   - `ExtractedByRepo::set` round-trips through the inbox view query;
