# M5 Recipes, meal plan and grocery list: Implementation Plan

**Status: skeleton.** The scope is settled (D-015, D-021, D-108), but most of the shape is in batch 24 (Q-098 to Q-114). This file fixes what is known and a tentative task cut so the briefs can be written as soon as the answers are processed. The contracts section is filled after `process-answers` re-derives [arch/Meals.md](../arch/Meals.md) (now draft v0).

## Why
- The user asked on 2026-11-07 to start M5 before M4.1 (D-108).
- Requirements: configurable horizon, generation from selected meals with normalisation and merge, add from the dashboard without a PIN, no export (D-015); one living list, archive after 24 h by default, staples check section (D-021).
- Checked against the code: `household.meal_plan_horizon_weeks` exists (default 2); `Action::AddGroceryItem` and `Resource::GroceryItem` exist in `fa-domain/src/authz.rs`; no meals tables, no `fa-meals` crate. `fa-recipe` (M4) holds `RecipeDraft`, the JSON-LD parser and a rule ingredient parser; `POST /ai/recipes/extract` stores nothing. `pg_trgm` ships in the `pgvector/pgvector:pg16` image (checked). Crate picks in [R-007](../research/R-007-ingredient-normalisation.md): `pluralizer` 0.6.0 (new), `strsim` and `scraper` (already workspace dependencies).

## Done means (draft)
1. An adult imports a recipe from a URL (JSON-LD or microdata page) or types one, edits the draft and saves it; unmatched ingredient lines are flagged.
2. The meal plan shows the horizon by week; entries are recipes or free text in configurable slots.
3. "Make grocery list" from a range or picked meals adds normalised, merged, scaled items; staples land in the Staples check section; running it twice adds nothing.
4. Anyone, the dashboard included without a PIN, adds and checks off items; checked items archive after the configured hours; all clients update live.
5. Settings → Meals edits slots, aisles, the catalogue and staples, and each toggle batch 24 made configurable.
6. The rest per the answers to Q-098 to Q-114.
7. CLAUDE.md workflow 8: `scripts/ci-local.sh`, `scripts/e2e.sh`, `scripts/compose-smoke.sh` green; README updated and its steps verified by running them.

## Contracts fixed up front

- `RecipeDraft`, `RecipeIngredient`, `RecipeOrigin` move to `fa-domain` (AI.md §9); `fa-recipe` re-exports them so its callers keep compiling. `RecipeOrigin` gains `microdata` if Q-098 keeps microdata.
- New crate `fa-meals`; the root `Cargo.toml` (workspace member, `pluralizer = "0.6"`) is the main session's.
- One migration file owned by the domain/store task; the `household` table keeps `meal_plan_horizon_weeks`.
- Every date is `YYYY-MM-DD`, slot times `"HH:MM"` local, timestamps RFC 3339.
