### C-10 secrets AAD (T-02)
- `MasterKey::seal(&self, plaintext: &[u8], aad: &[u8])` and `open(&self, sealed: &SealedSecret, aad: &[u8])`. The DEK wrap keeps the key version as its own AAD; `rewrap` is unchanged.
- AAD strings (UTF-8, uuids hyphenated lowercase): secrets `secret:v1|{household_id}|{owner_type}|{owner_id}|{kind}`; instance settings `instance_setting:v1|{key}`.
- Migration `crates/fa-store/migrations/20261102000001_secret_aad.{up,down}.sql`: `aad_version SMALLINT NOT NULL DEFAULT 0` on `secret` and `instance_setting`. `0` = sealed without AAD (opened with an empty AAD), `1` = bound.
- `SecretRepo::rebind_all(conn, key) -> Result<u64>` and `InstanceSettingRepo::rebind_all` re-seal every `aad_version = 0` row (open with empty AAD, seal with the AAD, set 1) in one transaction, modelled on the existing `rewrap_all`. `fa-server` runs both after migrations at startup and logs the counts; a failure is logged, not fatal, and the lazy fallback (opening a version-0 row with empty AAD) stays so old rows keep working.
- `get` opens with the row's `aad_version` (0 → empty AAD, 1 → the AAD). A row whose owner columns were changed under it fails with `StoreError::Crypto`.

### C-14 list envelopes (T-03)
- Concrete page DTOs in `fa-domain`, shaped like `MessagePage`: `TaskPage { items: Vec<TaskView>, next_before }`, `BillPage`, `InboxPage` (`items` keeps the existing inbox item type), `OrgPage`, `SessionPage`. `next_before: Option<DateTime<Utc>>` (RFC 3339, `#[ts(optional = nullable)]`), `None` when the page is the last.
- Query parameters on every one of the five lists: `before: Option<DateTime<Utc>>` (the previous page's `next_before`) and `limit: Option<u32>` (default 50, max 200; above the max is clamped, not an error). Existing filters stay.
- Ordering is keyset on `(created_at DESC, id DESC)` unless the handler already orders by something else that is stable; then the cursor is that column. The handler doc comment states which.
- The dashboard, `routines/today` and other bounded lists are untouched.
- Web: stores read `.items`; Bills, Inbox and Tasks views get a "Load more" button that appears while `next_before` is set; Orgs and Sessions read the first page only (bounded in practice) but through the envelope.

### C-13 route conventions (T-06)
Written into `arch/Platform.md` §4 as an "API naming" list:
- Collections are plural nouns; an item is `/{collection}/{id}`; a sub-collection is `/{collection}/{id}/{sub}` and its item `/{collection}/{id}/{sub}/{sub_id}`.
- An action on the **calling device or session** lives under the collection with no id: `POST /devices/elevate`.
- Dry runs: `validate` checks the payload alone (no I/O beyond the DB); `test` runs it against something (an external system, or stored data). Today's names already fit; the doc records which is which.
- The inbox keeps `{kind}` in its path as a sub-collection per proposal kind: `/inbox/{kind}/{id}/approve`.
- Renames: `POST /device/elevate` → `POST /devices/elevate`; `DELETE /away/{id}` → `DELETE /members/{member_id}/away/{id}`. Old paths stay as aliases marked `deprecated = true` in OpenAPI until M4 closes, listed in a "Deprecated aliases" table in §4.

### P-06 fa.py CLI (T-04)
`python3 tools/fa.py <subcommand> [--flags]`, keyword flags only, every long text flag also accepts `@path` to read the text from a file. Subcommands:
- `check`, `check-yaml <files>` (exist, unchanged).
- `next-id --kind q|d` prints the next free number.
- `new-q --n N --slug S --title T --area A --batch B --question TEXT [--option TEXT]...` (`--n` optional: next free).
- `new-d --id D-NNN --slug S --title T --questions Q-001,Q-002 --affects arch/X.md,arch/Y.md --context TEXT --decision TEXT --consequences TEXT --alternatives TEXT [--supersedes D-0NN]`, appends to `decisions/_index.md`.
- `resolve --q Q-NNN --decisions D-001,D-002 [--date YYYY-MM-DD]` (front-matter and `git mv`).
- `supersede --old D-0NN --new D-0MM --note TEXT`; `annotate --d D-0NN --note TEXT`.
- `log --topics a,b --text TEXT` appends to `log/<today>.md` (creates it with front-matter and adds the `log/_index.md` line if new).
- `status` writes `STATUS.md` at the repo root: open questions, open human steps, tasks not `done` in plans whose status is not closed, and the newest log date.
- `rebuild-design-index`.
- Every writer stamps `updated: <today>` in the index it touches. The library functions stay importable.
